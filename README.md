# coy · crush-on-you

用 Go + Bubble Tea 管理 **全局 `crushrc` 中的自定义 providers 和 models**。

提供商目录 / 模型文件双栏管理、模糊搜索与正则筛选、多选分组与折叠、批量删除、模型列表发现、表单校验、变更预览、保存前备份、原子替换及 dry-run。不管理 Crush 内置目录，不访问项目 `.crush/`，不执行配置脚本或调用模型推理 API。

## 运行

需要 Go 1.27.1 或更新版本：

```sh
go run ./cmd/coy
go run ./cmd/coy --dry-run
go run ./cmd/coy --check
```

`--dry-run` 打开同样的交互界面，允许编辑和预览，但所有保存操作都不写配置、不创建备份或目录。退出会丢弃草稿。

`--check` 是不启动 TUI 的只读语法与可编辑性检查；发现不支持的动态配置时非零退出。它不执行 Crush，也不验证服务连通性。

```sh
make build
./bin/coy --version
./bin/coy --config /absolute/path/to/crushrc --dry-run
```

默认全局路径依次由 `$CRUSH_GLOBAL_CONFIG/crushrc`、`$XDG_CONFIG_HOME/crush/crushrc`、`~/.config/crush/crushrc` 决定。`CRUSH_GLOBAL_CONFIG` 是**目录**。`--config` 显式指定文件，便于独立配置和临时目录测试；不会自动查找项目配置。

## 按键

| 按键 | 操作 |
| --- | --- |
| `n` | 新增提供商目录，确认表单后自动发现模型 |
| `m` | 在当前提供商目录下新增模型 |
| `↑` / `↓`、`j` / `k` | 在当前栏选择目录或模型 |
| `Tab` / `Shift+Tab` | 切换提供商栏 / 模型栏 |
| `→` / `l` / 提供商上的 `Enter` | 展开目录并进入模型栏 |
| `←` / `h` | 返回提供商栏；在提供商栏时折叠目录 |
| 空格 | 提供商 / 分组标题上展开或折叠；模型上切换多选 |
| `e` / 模型上的 `Enter` | 编辑当前栏选中的条目；分组标题上的 `Enter` 展开 / 折叠 |
| `/` / `?` | 模糊搜索 / 正则筛选当前提供商的模型；输入时 `Tab` 切换方式，`Enter` 应用，`Esc` 取消 |
| `Ctrl+L` | 清除模型筛选 |
| `Ctrl+A` / `Ctrl+U` | 用全部匹配模型替换选择 / 清空选择（包含折叠组中的匹配项） |
| `g` / `G` | 将多选模型加入一个分组 / 移出分组；未多选时作用于当前模型 |
| `r` | 重新获取当前提供商的模型列表，补充缺少的模型到草稿 |
| `d` | 删除多选模型，未多选时删除当前条目；列出待删 ID，需 `y` 确认 |
| `p` | 预览变更，不写入 |
| `s` / `Ctrl+S` | 保存，写入前需 `y` 确认；dry-run 下仅预览 |
| `q` / `Ctrl+C` | 退出；未保存时提示确认 |
| 表单内 `Tab` / `Shift+Tab` | 切换字段 |
| 表单内 `Enter` / `Ctrl+S` | 更新内存中的草稿 |
| `Esc` | 取消表单或返回列表 |

建议为自定义提供商使用独立 ID，例如 `my-openai`；`openai` 是内置 ID，不能在这里管理。API 类型可选 `openai`、`openai-compat`、`anthropic` 等；第三方 OpenAI 兼容服务通常使用 `openai-compat`。

API key 输入 `env:MY_API_KEY` 会生成 `--api-key "${MY_API_KEY}"`。其他新输入按 Shell 字面值转义，`$(...)` 不会意外变成命令；已有环境变量表达式不改动时保持原样。API key 始终遮蔽，预览也会隐藏 URL、名称等可能包含凭据的自由文本。

## 搜索、多选与逻辑分组

在模型栏按 `/` 使用 fzf 风格的模糊搜索：忽略大小写，按字符顺序匹配，连续字符和词首优先，空格分隔的词分别匹配。内置实现无需安装或启动 fzf，不提供 fzf 的完整查询语法。搜索范围是模型完整 ID 和静态名称，不执行名称里的 Shell 表达式。

按 `?` 输入 Go 正则表达式，例如 `gpt-(4|5)$`、`(?i)claude|gemini`。正则默认区分大小写；非法表达式会明确报错，不使用旧结果代替。搜索即时显示结果，`Enter` 应用后可用方向键、空格逐个选择，也可按 `Ctrl+A` 选择全部匹配项，再按 `g` 输入一个分组名或按 `d` 批量删除。删除前可用 `↑↓` 滚动核对完整 ID 列表，`n` / `Esc` 取消；任一条目被 `model large/small` 引用时，整批删除失败，草稿和选择保持原样。

每个模型属于至多一个逻辑分组，分组名限定在当前提供商内；输入同名分组会合并成员。分组标题上按空格或 `Enter` 折叠 / 展开，`→` 展开、`←` 折叠。筛选期间匹配组临时展开，清除筛选后恢复原来的折叠状态。更改筛选会保留多选，确认删除时包括隐藏的已选项；`Ctrl+A` 会用当前匹配项替换原选择，`Ctrl+U` 清空，切换提供商会清空选择。

分组先保存在草稿中，按 `s` 后以独立的 `# coy:model-group <完整模型ID> "分组名"` 注释写入同一份 `crushrc`，下次打开仍保留。Crush 忽略这些注释，模型 ID 和运行时配置保持原意；折叠状态仅在当前会话保留。分组操作与其他编辑共用预览、备份、冲突检测及 dry-run；预览隐藏分组名等自由文本。手动编辑配置时应同步删除已移除模型的分组注释；格式错误、重复或引用不存在模型的分组注释会让配置只读，并保留原文。

## 模型目录与自动发现

左栏的提供商相当于目录，右栏显示当前目录下的模型文件。新增提供商时填写 ID、API 地址和 API key（API 类型默认 `openai-compat`），确认后自动请求 `<API 地址>/models`，将返回的全部模型加入内存草稿并打开模型栏。无鉴权的本地服务可留空 key；禁用的提供商不会在创建时请求。发现结果按 ID 去重，已有模型及其配置保持原样。

新增或编辑模型时始终写入 `--name`。每次保存还会检查配置中全部静态 `model add` 命令，为缺失或空的名称补齐 `--name`，包括没有编辑过的旧条目；无需逐个打开模型表单。名称留空或发现接口仅返回 ID 时，使用去掉 provider 前缀后的完整模型 ID，例如 `model add 'hyb/google/gemma-3-4b-it' --name 'google/gemma-3-4b-it'`。已有非空名称及 Shell 表达式保留原样；预览和 dry-run 同样展示这些修复，正式保存前备份原件。

在模型栏用 `d`、`y` 删除不需要的模型，用 `e` 编辑，最后 `s` 保存。新增提供商默认写入 `--discover-models false`，由 coy 完成这一次发现；这样 Crush 不会在启动时把你删除的模型重新加回来。这个字段控制 **Crush 的运行时发现**，与 coy 的新增时发现、`r` 手动发现相互独立；若主动改为 `true`，Crush 仍可能补回删掉的模型。重新按 `r` 也会再次导入先前删去但服务仍返回的模型。

发现协议与 Crush 的通用发现一致：HTTP GET、Bearer API key、包含 `data: [{"id": "model-id"}]` 的完整 JSON 列表；API 地址应含服务要求的版本前缀，例如 `/v1`。不猜测模型能力、上下文长度或价格，可在模型表单中补充。需要其他认证协议、额外请求头或分页的服务当前不支持自动完整导入，仍可手动添加模型。请求不跟随重定向，15 秒超时，`Esc` 可取消；空列表、格式错误、鉴权失败及不支持的模型 ID 都明确报错，保留提供商草稿，修正后可按 `r` 重试。

发现只解析当前进程中的环境变量：支持新输入的 `env:变量名` 和已有的单个 `$VAR` / `${VAR}` 引用；不执行 Shell，不解析变量默认值、拼接或凭据命令。只有新增提供商或按 `r` 才访问模型列表接口，打开已有配置不会自动联网。dry-run 同样可以发现并删选模型，但不写入文件。

## 配置与安全边界

- 直接生成标准 `provider add` / `model add` 命令；分组使用同文件注释，不维护平行数据库。
- 可编辑顶层、单次定义、使用 `--flag value` 参数的条目。支持多行续行和引用；已有额外参数、注释及无关设置保留原文。内置条目不提供编辑操作，保存时仅对其中的静态 `model add` 补齐缺失或空的 `--name`。
- provider 表单支持名称、类型、地址、API key、禁用、自动发现和固定费率；model 表单支持名称、上下文、输出 token 上限、推理/图片能力、价格和推理强度。其他参数原样保留，当前不提供表单编辑。
- `source`、控制流、命令替换、重复定义、重定向及无法确定语义的脚本明确设为只读。不会运行 Shell 来“发现”配置，不自动迁移旧 JSON。
- 只读取显式自定义 provider 及其模型；内置 provider 上的模型、Crush 的自动发现缓存和运行时状态不纳入管理。coy 主动发现的模型经用户删选、保存后成为显式 `model add` 条目。内置 ID 保护名单依据 2026-10-25 的 [Catwalk provider 定义](https://github.com/charmbracelet/catwalk/blob/main/pkg/catwalk/provider.go)及 Crush Hyper；后续新增的内置 ID 需要更新名单。
- ID 创建后不可重命名。删除 provider 前先删除其模型；被 `model large/small` 引用的条目不能删除，需先在 Crush 中调整选择。
- 已有文件每次实际变更前创建同目录 `crushrc.backup-*`，保留完整原始内容并限制为仅文件所有者可访问。备份失败停止写入。无变化不生成备份；首次创建时明确提示无原件可备份。
- 保存会检测外部变更，以独占锁协调多个 coy 实例，并使用同目录临时文件、同步文件内容及原子重命名。符号链接和特殊文件不予覆盖。与不遵守锁的其他编辑器仍存在最后检查到重命名间的短暂竞争窗口，编辑时请避免并行保存同一文件。
- 备份路径在保存后显示。恢复前退出编辑器并核对备份，再手动将所选备份复制回 `crushrc`。不自动删除历史备份。

配置命令契约依据 [Crush 配置文档](https://github.com/charmbracelet/crush/tree/main/docs/config)（2026-10-25 上游 main）。目标 Crush 需支持 `crushrc`；只支持旧 JSON 的旧版不适用。

## 开发与打包

```sh
make check
go test -race -timeout 60s ./...
make dist VERSION=v0.1.0
```

测试均使用临时文件，不触碰真实全局配置。覆盖原文保留、引号转义、内置边界、引用、备份、dry-run、外部冲突、凭据遮蔽和 TUI 操作。

`dist/` 包含 Linux amd64/arm64、macOS amd64/arm64、Windows amd64 的原始二进制和 `SHA256SUMS`，不是压缩包。下载到同一目录后运行 `sha256sum --check --ignore-missing SHA256SUMS`；Linux/macOS 的二进制需添加执行权限。

GitHub Actions 在 push/PR 时执行验证；`v*` 标签通过验证后构建并发布 Release。开发分支推送不会创建 Release。
